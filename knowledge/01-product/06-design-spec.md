## Context

TrueCare is a React Native mobile app (consumer + merchant, role-based) plus
ops-managed growth/export references. The definitive UI reference is the P0
Screen Manifest: one shared manifest for PRD, design, the HTML artifact, and
implementation backlog.

P0 implementation productizes the consumer and merchant core flows for 12-20
live curated merchants. Acquisition uses invite/referral codes and ops-managed
channel tracking. Merchant accounts cannot take real bookings until manual ops
verification sets them live. Control tower reporting, SLA watch,
complaint/refund review, and growth attribution remain human-operated workflows
using SQL/export/dashboard-lite, structured exports, and runbooks. The richer
control tower remains the product reference for P1 automation.

The P0 design target is a world-class ServiceOS: the product thinks ahead, the
user confirms one obvious next action, and every operational state is shared by
consumer app, merchant console, payment/evidence flows, and ops exports. P0
preserves TrueCare state while allowing two explicit external handoffs: Apple
Maps / Google Maps for directions and the user's bank app for QR transfer.

Current P0-Final uses QR/bank transfer as the primary payment rail, cash as
fallback, GPS 5km list discovery, merchant-scans-user-QR check-in, and VETC
Wallet / Loyalty only as disabled placeholder or Route Moat Gate scope unless
the relevant VETC contracts pass.

## Pass 3: User Journey & Emotional Arc — 5/10 → 9/10

### Consumer Journey (Anh Tuan)

```
STEP | USER DOES              | USER FEELS           | DESIGN SUPPORTS
─────┼────────────────────────┼──────────────────────┼────────────────────────────
  1  | Opens app              | "Do I need a wash?"  | Reminder card: "8 ngay chua rua" + local context
  2  | Sees recommendations   | "Which shop is best?" | Ranked cards: distance, wait, price, Gio Vang
  3  | Taps "Giu cho"         | "Will it work?"       | Instant confirmation: green check icon + countdown

  5  | Approaches merchant    | "They are ready"      | Active booking countdown, QR, fallback code, bay readiness
  6  | Arrives, shows QR      | "Did they see me?"    | Merchant scans → Green check animation, bay assignment
  7  | Waits / car is washed  | "How long left?"      | Service progress, evidence state, point hold visible
  8  | Pays QR/cash           | "Simple, trusted"     | Merchant QR/bank details, cash fallback, VETC disabled placeholder
  9  | Rates: Hai long? ✓/✗  | "Quick, done"         | One-tap binary + optional comment
 10  | Gets proof/recovery    | "There is accountability" | Evidence photos, complaint/refund/point reversal
 11  | Next time, returns     | "This app remembers my car" | Booking history, reward progress, local reminders
```

**Emotional arc peaks:**
- 5-sec visceral: urgency card (orange/red) creates "oh, I should do this"
- 5-min behavioral: slot hold countdown creates commitment + relief
- 5-year reflective: "this is the app that knows my car better than I do"

**Journey breaks fixed:**
- Post-hold void → Booking Active screen with countdown, user QR, fallback code, and shared two-device state
- Navigation uncertainty → external Maps handoff plus TrueCare resume/refetch keeps booking context current
- Merchant uncertainty → Queue Board shows held bay, user QR scan action, and payment confirmation state
- Rating fatigue → Binary rating (decided above), one tap

### Merchant Journey (Shop owner)

```
STEP | MERCHANT DOES           | MERCHANT FEELS        | DESIGN SUPPORTS
─────┼─────────────────────────┼───────────────────────┼────────────────────────────
  1  | Opens app morning       | "How busy today?"     | Stats: 0 done, 5 bays open, no queue
  2  | Gets booking alert      | "Customers coming!"   | M1 ping: "Khach TrueCare, 14:45, Bay 2"
  3  | Taps "Mo nhan"          | "Let's go"            | Bays update, queue populates
  4  | Scan customer QR       | "Smooth check-in"     | Scan user QR → customer confirmed → before photo
  5  | Takes before photo      | "Quick, routine"      | Camera → one-tap capture
  6  | Completes service       | "Done"                | After photo → mark complete
  7  | End of day, checks sum  | "How did I do?"       | Revenue + ratings + fill rate
```

**Merchant emotional design:**
- Reduce stress, don't add it. Merchant's day is physical work.
- Numbers (bay count, queue depth) must be instantly scannable
- Alerts must be SHORT. "Khach 14:45, Bay 2, Rua ngoai." Not paragraphs.

### Rating Change: Binary (Vietnamese market insight)

```
BEFORE: ★ ★ ★ ★ ☆  (5-star, 90% will be 5-star, useless signal)
AFTER:  [thumb_up] Hai long / [thumb_down] Chua hai long + optional comment
```

Why: Vietnamese rating culture defaults to 5 unless furious. Binary captures real sentiment. Better signal for merchant quality scoring engine.

## Pass 6: Responsive & Accessibility — 4/10 → 8/10

### Responsive Behavior

### Accessibility Specs

| Requirement | Spec | Why |
|---|---|---|
| Touch targets | 48px minimum (not 44px, per Android guidelines) | Merchant users have wet/dirty hands |
| Color contrast | 4.5:1 minimum text, 3:1 large text (WCAG AA) | Outdoor use in bright sunlight |
| Focus indicators | 2px VETC green outline on focusable elements | Keyboard navigation for Control Tower |
| Screen reader | All images have alt text. Buttons have labels. | Baseline a11y |
| Status colors | Never rely on color alone. Add text/icon. | Bay status: green dot + "Trong" text |
| Vietnamese diacritics | line-height >= 1.5, font: Be Vietnam Pro | Prevent clipping on Android |

### Merchant-Specific UX (Codex finding #6: merchants may not manage digital tools well)
- Buttons: larger (56px height on merchant app vs 48px on consumer)
- Text: 15px minimum body (vs 14px consumer)
- Feedback: haptic + visual for every tap (merchant is often not looking at screen)
- Offline: Queue board must work with 2-3 second network latency (optimistic updates)
